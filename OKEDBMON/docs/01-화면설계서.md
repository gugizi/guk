# OKEDBMON 화면 설계서

- 제품명: OKEDBMON
- 버전: 1.0.0.0
- 기준일: 2026-11-14
- 대상 DBMS 순서: Oracle, Tibero, MariaDB, PostgreSQL

화면은 수집서버에 저장된 값만 조회한다. 에이전트가 멈춘 뒤에도 이미 쌓인 세션과 SQL은 남는다. 새 수집은 에이전트가 실행 중일 때만 들어온다.

`config/agent.json`의 `mode`가 `simulate`이면 DB에 접속하지 않고 같은 형식의 샘플을 보낸다. 성능 테이블이 비어 있는 수집 DB로 수집서버를 처음 띄우면 등록된 인스턴스의 최근 1시간 샘플이 채워진다.

## 1. 공통 레이아웃

| 영역 | 설명 |
|---|---|
| 로그인 | User ID / Password. 초기 계정 `admin` / `okedbmon`. 제목은 `OKEDBMON V1.0.0.0` |
| 상단바 | 로고, 버전, 조회 메뉴, 상태 칩(All, Start, Down, Warning, Critical), 사용자, 환경 메뉴 |
| 좌측 | DBMS별 인스턴스 목록. 이름과 호스트로 검색 |
| 본문 | 선택한 인스턴스와 메뉴의 조회 결과 |

공통 규칙

- 로고를 누르면 통합 관제(첫 화면)로 간다.
- 자동 갱신은 통합 관제, Current, Active Session, Lock에서 5초마다 동작한다.
- 상세 창이 열려 있거나 입력 중이면 자동 갱신을 건너뛴다.
- 로그인 토큰은 브라우저 `localStorage` 키 `okedbmon_token`에 둔다. 선택한 인스턴스는 `okedbmon_alias`다.
- 좌측에서 인스턴스를 바꾸면 현재 조회 메뉴를 유지한다.

## 2. 메뉴 구조

```
로그인
 └─ 통합 관제
실시간
 ├─ Current, Active Session, Lock, Event
성능 분석
 ├─ Session History, 시점별 Session, SQL, 추이, 점검 요약
환경설정
 ├─ Config, 보관 주기
```

## 3. 화면 정의

### 3.1 통합 관제

- 인스턴스 카드에 CPU, Memory, Active Session, Lock Wait, Buffer Hit, Connected를 표시한다.
- 오른쪽에는 CPU, Memory, Active Session, Lock Wait 추이를 인스턴스별로 겹쳐 그린다.
- 아래에는 Event List와 Slow SQL이 있다.
- 상태 칩은 전체, 기동, 중지, 주의, 임계 건수다.

### 3.2 실시간

- Current는 선택 인스턴스의 세션, 시스템, 워크로드 요약과 마지막 수집의 Active Session, Lock 트리를 보여 준다.
- Active Session은 마지막 수집 시각의 세션 목록이다. 행을 누르면 SQL 전문이 아래에 나온다.
- Lock은 `blocking_sid`가 있는 대기 세션과 Lock 트리다.
- Event는 임계치를 넘긴 수집 이벤트 목록이다.

### 3.3 성능 분석

- Session History는 시작·끝 시각으로 세션 이력을 조회한다. 빠른 선택은 1시간, 6시간, 12시간, 1일, 7일이다. 한 번에 최대 200행이다.
- 시점별 Session은 수집 1회를 막대 하나로 그린다. 세로축은 그 수집의 Active Session 수다. 막대 또는 조회 시점을 고르면 그 `agent_collect_tm`의 세션 상세가 아래에 나온다. 그래프는 최근 120회 수집이다.
- SQL은 SQL 하나당 점 하나의 수행시간 분포다. 가로는 수행 횟수, 세로는 회당 수행시간(ms)이다. 점을 누르면 SQL Trace가 열린다. 행을 누르면 SQL 상세정보 창이 열린다.
- SQL 상세정보는 SQL ID, 유형, 사용자, 처음·마지막 수집 시각, 수행, Elapsed, CPU, Buffer Gets, Disk Reads, Rows, SQL 전문이다.
- SQL Trace는 같은 분포도에서 선택한 SQL만 주황 점으로 표시하고, 그 SQL이 잡힌 세션 샘플(시점, SID, Wait, Elapsed)을 보여 준다. 샘플은 최근 40건이다.
- 추이는 CPU, Memory, Active Session, Buffer Hit의 최근 1시간 선 그래프다.
- 점검 요약은 최근 6시간의 CPU·세션 요약과 Top SQL이다.

### 3.4 환경설정

- Config는 제품 제목, 버전, 수집 주기, 임계치(CPU, Active Session, Lock, Buffer Hit), 에이전트 토큰, 인스턴스 등록이다. DB 비밀번호는 이 화면에 다시 표시하지 않는다.
- 보관 주기는 수집서버의 데이터 종류별 보관일수다. 사용을 끄면 그 종류는 삭제하지 않는다. 보관일수 0은 현재 시각보다 이전 데이터를 삭제한다.

| 데이터 | 기본 보관일 |
|---|---|
| DB 성능 정보 | 14 |
| Active Session | 2 |
| Session History | 7 |
| SQL 수행 통계 | 14 |
| SQL Text | 30 |
| 이벤트 | 30 |

## 4. 권한

이 버전의 로그인 역할은 초기 계정 `admin` 하나다. 화면별 권한 키, Session Kill, Trace ON/OFF는 없다.

## 5. 화면 흐름

로그인 → 통합 관제. 좌측에서 인스턴스를 고르면 같은 메뉴가 그 대상으로 다시 그려진다. 성능 분석의 그래프에서 시점이나 SQL 점을 고르면 그 대상의 상세가 열린다.
