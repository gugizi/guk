# OKEDBMON 인프라 및 배포 가이드

- 버전: 1.0.0.0
- 기준일: 2026-11-14
- 배포 형태: 소스 실행. Python 3.10 이상이 있는 Windows, Linux, WSL

## 1. 아키텍처

```
[브라우저] -> [수집서버 :8080] <- [DB 서버 에이전트] -> [DBMS]
                    |
             data/okedbmon.sqlite
             성능, 세션, SQL, 환경설정
```

수집서버는 성능, Active Session, Session History, SQL Text, SQL 통계, 이벤트, 로그인, 환경 설정을 한 SQLite에 둔다. 에이전트 프로세스 하나는 그 서버의 인스턴스 하나만 수집한다.

## 2. 요구 사항

| 항목 | 최소 |
|---|---|
| OS | Windows 10/11, Linux, WSL |
| Python | 3.10 이상 |
| 브라우저 | Chrome, Edge |
| 포트 | 수집서버 8080 |
| 디스크 | 프로그램 + `data/okedbmon.sqlite` 증가분 |

Oracle은 `oracledb`, MariaDB는 `pymysql`, PostgreSQL은 `psycopg`가 `requirements.txt`에 있다. Tibero는 `TIBERO_JDBC_JAR`와 `jaydebeapi`를 그 DB 서버에 따로 둔다.

## 3. 실행 파일

프로그램은 `OKEDBMON` 폴더에 있다.

| OS | 수집서버 | 에이전트 |
|---|---|---|
| Windows | `run_collector.bat` | `run_agent.bat` |
| Linux / WSL | `./run_collector.sh` | `./run_agent.sh` |

첫 실행은 `.venv`를 만들고 패키지를 설치한다. 수집서버를 먼저 띄운다.

## 4. 설치

1. 저장소를 받는다. `git clone https://github.com/gugizi/guk.git`
2. `OKEDBMON` 폴더에서 수집서버를 실행한다.
3. 브라우저에서 `http://127.0.0.1:8080/` 을 연다. 초기 계정은 `admin` / `okedbmon`이다.
4. 상단에 `OKEDBMON V1.0.0.0`이 보이는지 확인한다.
5. DB 서버마다 `config/agent.json`을 두고 `run_agent`를 실행한다. `target`은 하나다.
6. `agent_alias`를 수집서버 인스턴스 목록과 맞춘다. `token`은 수집서버 `agent.token`과 같게 한다.
7. 다른 PC에서 화면을 보려면 `http://<수집서버 IP>:8080/` 을 쓰고 방화벽에서 8080을 연다.

샘플만 보려면 `config/agent.json`의 `mode`를 `simulate`로 둔다. 실 DB는 `mode`를 `live`로 바꾸고 `host`, `port`, `database`, `user`, `password`를 넣는다. 비밀번호는 이 파일에만 둔다.

## 5. 버전 관리

형식은 주.부.수정.빌드 네 자리(`A.B.C.D`)이다.

| 자리 | 이름 | 올리는 때 |
|---|---|---|
| A | 주 | 저장 방식이나 호환이 바뀌는 변경 |
| B | 부 | 기능 묶음 |
| C | 수정 | 같은 형태 안의 기능·수정 |
| D | 빌드 | 같은 수정 번호의 패치 |

1. `collector/version.py`의 `VERSION`을 바꾼다.
2. `config/default.properties`의 `support.ver`를 같은 값으로 바꾼다.
3. `CHANGELOG.md`에 항목을 추가한다.
4. 화면 파일을 바꿨으면 `web/index.html`의 `?v=`를 올린다.

## 6. 모니터 계정

실 DB에는 조회 전용 계정을 쓴다. 비밀번호는 `config/agent.json`에만 둔다.

| DBMS | 필요 권한 |
|---|---|
| Oracle | `CREATE SESSION`, `V$SESSION`, `V$SQL`, `V$SYSSTAT` 조회 |
| Tibero | 세션과 `V$` 조회. JDBC 드라이버 |
| MariaDB | `PROCESS`, 가능하면 `performance_schema` |
| PostgreSQL | `pg_stat_activity` 조회 |

## 7. 로그와 데이터 위치

| 대상 | 위치 |
|---|---|
| 수집 DB | `OKEDBMON/data/okedbmon.sqlite` |
| 수집서버 설정 | `config/default.properties` |
| 에이전트 설정 | 그 DB 서버의 `config/agent.json` |
| Python 패키지 | `OKEDBMON/.venv` |

`data/`와 `.venv`는 Git에 넣지 않는다.

## 8. 백업

수집서버를 멈춘 뒤 `data/okedbmon.sqlite`와 `-wal`, `-shm`을 복사한다. 에이전트 비밀번호는 `config/agent.json`을 따로 보관한다.

## 9. 업데이트

1. 수집서버와 에이전트 창을 닫는다.
2. `data/okedbmon.sqlite`를 복사해 둔다.
3. 새 소스를 받는다.
4. 수집서버를 다시 실행한다. 기존 SQLite는 그대로 연다.
5. 화면의 `OKEDBMON V` 버전을 확인한다. 화면이 옛 파일이면 새로고침한다.

## 10. 점검

| 확인 | 기대 |
|---|---|
| `/api/health` | `display`가 `OKEDBMON V1.0.0.0` |
| 로그인 | 통합 관제. 좌측에 인스턴스 |
| 수집 | 에이전트 창에 `collected <별칭>:ONLINE` |
| 세션 | 실시간 Active Session에 행 |
| 시점 | 성능 분석 · 시점별 Session 막대를 누르면 그 시각의 상세 |
| SQL | 성능 분석 · SQL에 점 하나당 SQL 하나. 점을 누르면 SQL Trace |
| 보관 | 여섯 종류와 건수 |

## 11. 장애

| 증상 | 조치 |
|---|---|
| 로그인이 풀림 | 수집서버를 한 번만 실행한다. 토큰은 12시간이다 |
| 수집 거부 | `X-Agent-Token`과 수집서버 `agent.token` |
| 에이전트가 시작하지 않음 | `target`이 하나인지 확인 |
| 세션이 비어 있음 | 에이전트가 그 별칭으로 한 번 이상 수집했는지 확인 |
| Tibero 연결 실패 | `TIBERO_JDBC_JAR`, `jaydebeapi`, 포트, 계정 |
| 화면이 옛 구성 | 새로고침. `index.html`의 `?v=` 확인 |
