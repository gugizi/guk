# OKEDBMON 소스 설명서

- 버전: 1.0.0.0
- 기준일: 2026-11-14
- 설명 대상: `OKEDBMON/` 아래 수집서버, 에이전트, 화면

이 문서는 소스를 처음 여는 사람이 파일 역할과 실행 순서를 따라가도록 적었다. 화면 항목은 [01-화면설계서.md](01-화면설계서.md), 저장 컬럼은 [04-테이블정의서.md](04-테이블정의서.md), 요청 경로는 [05-API명세서.md](05-API명세서.md), 서버를 나누는 방법은 [08-분산수집구성.md](08-분산수집구성.md)를 본다.

## 1. 프로그램이 하는 일

DB 서버마다 에이전트 프로세스 하나가 그 서버의 인스턴스만 읽는다. 읽은 Active Session, Session History, SQL Text, SQL 통계, 성능 수치를 수집서버 `POST /api/ingest`로 보낸다. 수집서버는 `data/okedbmon.sqlite`에 저장하고, 브라우저 화면이 그 파일을 조회한다. 에이전트는 조회 포트를 열지 않는다.

```
config/agent.json
    └─ agent/__main__.py
         └─ agent/runtime.py          한 주기마다 collect()
              └─ agent/collectors.py  live
              └─ agent/simulate.py    simulate
                   └─ POST /api/ingest
                        └─ collector/server.py
                             └─ collector/store.py   data/okedbmon.sqlite
                                  └─ web/app.js      브라우저 조회
```

## 2. 폴더

| 경로 | 역할 |
|---|---|
| `collector/` | 수집서버. FastAPI, SQLite, 보관 주기, 정적 화면 제공 |
| `agent/` | DB 서버에 두는 수집 프로세스 |
| `web/` | 로그인과 조회 화면. 빌드 단계 없음 |
| `config/default.properties` | 수집서버 제목, 포트, 토큰, 임계치, 보관일수, SQLite 경로 |
| `config/agent.json` | 이 프로세스가 맡을 인스턴스 하나와 수집서버 주소 |
| `tests/test_monitor.py` | 로그인, 수집, 보관, 시점 조회, 에이전트 설정 |
| `run_collector.sh`, `run_collector.bat` | 가상환경을 만들고 `python -m collector` |
| `run_agent.sh`, `run_agent.bat` | 가상환경을 만들고 `python -m agent` |
| `requirements.txt` | FastAPI, uvicorn, httpx, pydantic, pymysql, psycopg, oracledb, pytest |

버전 원본은 `collector/version.py`의 `VERSION`이다. 형식은 `1.0.0.0` 네 자리다. 화면 문구는 `display_name()`이 `OKEDBMON V1.0.0.0`으로 만든다.

## 3. 기동

수집서버 스크립트는 `OKEDBMON`으로 이동한 뒤 `.venv`가 없으면 만들고 `requirements.txt`를 설치한다. 그 다음 `python -m collector`를 실행한다.

`collector/__main__.py`의 `main()`은 다음 순서로 동작한다.

1. `load_properties()`로 `config/default.properties`를 읽는다.
2. `create_app()`이 `Store`를 만들고 FastAPI 앱을 만든다.
3. `build_demo_history()`는 `o_performance`가 비어 있을 때만 과거 1시간을 채운다. 이미 행이 있으면 아무 것도 넣지 않는다.
4. `collector.host`, `collector.port`로 uvicorn을 띄운다. 기본은 `0.0.0.0:8080`이다.

`build_demo_history()`는 등록된 인스턴스마다 `Simulator`를 만들고, 60분 전부터 5초 전까지 20초 간격으로 `store.ingest()`를 호출한다. 처음 화면의 차트는 이 채우기이거나, 그 뒤에 도착한 에이전트 수집분이다.

에이전트 스크립트는 `python -m agent`를 실행한다. `agent/__main__.py`는 `config/agent.json`을 읽고 `resolve_target()`으로 인스턴스 하나를 고른 뒤 `serve_target()`에 넘긴다.

## 4. 수집 한 주기

`agent/runtime.py`의 `serve_target()`이 끝없이 반복한다.

1. `target_interval()`이 주기를 정한다. 대상의 `interval_sec`가 있으면 그 값이고, 없으면 설정의 `interval_sec`다. 최소는 2초다.
2. `make_collector()`가 수집기를 고른다. `mode`가 `live`가 아니면 `Simulator`다.
3. `collect()`가 페이로드를 만든다. 예외가 나면 `empty_error()`로 상태만 `ERROR`인 페이로드를 만든다. 프로세스는 다음 주기를 계속한다.
4. `post_payload()`가 `collector_url` + `/api/ingest`로 JSON을 보낸다. 헤더는 `X-Agent-Token`이다.
5. 남은 시간만큼 잔다. 수집과 전송에 쓴 시간은 주기에서 뺀다.

`resolve_target()`은 `target` 객체 하나를 요구한다. `target`과 `targets`를 같이 두거나, `targets`에 인스턴스가 둘 이상이면 `AgentConfigError`로 기동을 멈춘다. 목록에 항목이 하나뿐이면 그 항목을 단일 대상으로 받아들인다.

## 5. 에이전트 소스

### `agent/collectors.py`

`make_collector()` 분기:

| 조건 | 클래스 | 접속 |
|---|---|---|
| `mode`가 `live`가 아님 | `agent/simulate.py`의 `Simulator` | DB에 접속하지 않음 |
| `ORACLE` | `OracleCollector` | `oracledb`. `V$SESSION`, `V$SQL`, `V$SYSSTAT` |
| `TIBERO` | `TiberoCollector` | `jaydebeapi`. 환경변수 `TIBERO_JDBC_JAR` 필요. Oracle과 같은 `V$` 조회 |
| `MARIADB` | `MariaCollector` | `pymysql`. `SHOW GLOBAL STATUS`, `information_schema.processlist`, 가능하면 `performance_schema` |
| `POSTGRESQL` | `PostgresCollector` | `psycopg`. `pg_stat_database`, `pg_stat_activity`, 확장이 있으면 `pg_stat_statements` |

`LiveBase`가 공통 처리를 맡는다.

- `delta()`, `delta_fields()`는 누적 카운터를 이전 샘플과의 차이로 바꾼다. 첫 샘플의 차이는 0이다.
- `envelope()`가 수집서버가 받는 공통 JSON을 만든다. 키는 `agent_alias`, `product`, `collect_tm`, `version`, `status`, `message`, `performance`, `active_sessions`, `session_history`, `sql_texts`, `sql_stats`다.
- Active 세션만 `source`를 `sample`로 해서 `session_history`에 넣는다.

Oracle 성능 계산은 `_pack()`에 있다. 커밋, 실행, 물리 읽기, 논리 읽기, redo, hard parse를 주기로 나누거나 차이로 만든다. 버퍼 적중률은 물리 읽기와 논리 읽기 비율이다. CPU와 메모리는 `agent/osmetrics.py`가 Linux `/proc/stat`, `/proc/meminfo`에서 읽는다. 파일이 없으면 값은 비운다.

SQL 식별자는 `fingerprint()`가 문장 해시로 만든다. 시뮬레이터는 `sql_id()`로 SHA1 앞 13자를 쓴다.

### `agent/simulate.py`

`CATALOG`에 DBMS별 예시 SQL이 있다. `collect()`는 별칭과 시각으로 물결 형태의 CPU, 세션, Lock, SQL 통계를 만든다. 화면을 확인할 때와, 수집서버가 빈 저장소를 처음 채울 때 이 형식을 쓴다. `live` 수집이 실패하면 이 샘플로 바꾸지 않고 오류 상태만 보낸다.

### `agent/osmetrics.py`

`read_host_metrics()`가 CPU 사용률과 메모리 사용률을 돌려준다. 테스트는 임시 `/proc` 파일로 확인한다.

## 6. 수집서버 소스

### `collector/server.py`

`create_app()`이 라우트를 등록한다. 화면 사용자는 `Authorization: Bearer <토큰>`이 필요하다. `current_user()`가 토큰을 검사하고, 없거나 만료면 401이다. 에이전트 수신만 `X-Agent-Token`을 `agent_authorized()`로 확인한다.

| 경로 | 함수 | 하는 일 |
|---|---|---|
| `GET /api/health` | `health` | 제목, 버전, `OKEDBMON V1.0.0.0` 표시 문구. 로그인 없음 |
| `POST /api/login` | `login` | 성공하면 토큰 |
| `GET /api/me` | `me` | 현재 사용자 |
| `GET /api/dashboard` | `dashboard` | 인스턴스 상태와 요약 |
| `GET,POST /api/instances`, `PUT,DELETE /api/instances/{alias}` | 인스턴스 등록 | `mon_instance` |
| `GET,PUT /api/settings` | 환경설정 | `env_setting`. `agent.token`은 `********`로 가린다 |
| `GET,PUT /api/retention`, `POST /api/retention/run` | 보관 | 정책 조회, 수정, 즉시 삭제 |
| `GET /api/performance` | `performance` | 구간 성능 시계열 |
| `GET /api/sessions/times` | `session_times` | 수집 시각 목록 |
| `GET /api/sessions/series` | `session_series` | 수집 1회당 Active Session 수 |
| `GET /api/sessions/active` | `active_sessions` | 그 시각의 세션과 Lock 트리 |
| `GET /api/sessions/history` | `session_history` | 구간 세션 이력. `sql_id`로 거를 수 있다 |
| `GET /api/sql`, `GET /api/sql/detail` | SQL 목록과 상세 | 문장, 합계, 최근 통계, `session_history`의 그 SQL 샘플 |
| `GET /api/events` | `events` | 임계치 이벤트 |
| `GET /api/report` | `report` | 구간 평균과 최대 |
| `POST /api/ingest` | `ingest` | 에이전트 페이로드 저장 |
| `GET /` | `index` | `web/index.html` |
| `/static` | 정적 파일 | `web/` |

`_lock_tree()`는 세션의 `blocking_sid`로 부모와 자식을 묶어 Lock 화면의 트리를 만든다.

`_start_retention_loop()`는 데몬 스레드 `retention`을 하나 띄운다. `retention.purge.interval.sec`마다 `store.purge()`를 호출한다. 주기가 잘못되면 60초를 쓴다. 최소 간격은 15초다.

### `collector/store.py`

SQLite 연결과 모든 저장이 이 파일에 있다.

연결은 스레드마다 따로 둔다. `conn` 속성이 `threading.local`에서 연결을 꺼내고, 없으면 `_connect()`로 만든다. WAL 모드와 `busy_timeout` 5초를 켠다. 요청을 처리하는 스레드가 다른데 연결을 하나만 쓰면, 방금 발급한 로그인 토큰이 다음 조회에서 빠질 수 있다. 쓰기는 `self._lock` 안에서 한다.

`_seed()`는 처음 열 때 다음을 넣는다. 이미 있는 키는 덮어쓰지 않는다.

- `default.properties`의 키를 `env_setting`에 넣는다.
- `RETENTION_KINDS`의 보관 정책을 넣는다.
- 사용자가 없으면 `admin` / `okedbmon`을 만든다. 비밀번호는 `hash_password()`가 PBKDF2-HMAC-SHA256으로 저장한다.
- 인스턴스가 없으면 Oracle, Tibero, MariaDB, PostgreSQL 예시 네 개를 넣는다.

`_migrate_identity()`는 예전 이름 SpaceMon, OKEMON이 남아 있으면 제목을 OKEDBMON으로 바꾸고, 세 자리 버전은 `1.0.0.0`으로 바꾸며, 예전 저장 경로와 예전 에이전트 토큰도 현재 값으로 바꾼다.

`ingest()`는 한 트랜잭션에서 다음을 저장한다.

1. `agent_heartbeat`를 업서트한다.
2. 성능이 있으면 같은 별칭, 같은 시각의 `o_performance`를 지우고 다시 넣는다. 이어서 `_raise_threshold_events()`가 CPU, Active Session, Lock, 버퍼 적중률을 임계치와 비교해 `event_log`에 남긴다.
3. 같은 시각의 `active_session`을 지우고 받은 세션을 넣는다.
4. `session_history`에 이력 행을 넣는다. `source` 컬럼이 있다.
5. `sql_text`는 `(agent_alias, sql_id)`가 있으면 문장과 `last_seen`을 갱신한다.
6. `sql_stat`은 수집 시각마다 행을 추가한다.

`purge()`는 `retention_policy`에서 사용 중인 종류만 지운다. 보관일수만큼 지난 행을 삭제하고 `purge_log`에 건수를 남긴다. 보관일수 0은 현재 시각보다 이전 행을 지운다. 사용을 끈 종류는 지우지 않는다.

조회 메서드는 화면과 같은 이름이다. `dashboard()`, `latest_performance()`, `performance_series()`, `current_sessions()`, `session_times()`, `session_series()`, `session_history()`, `sql_catalog()`, `sql_detail()`, `events()`, `report()`, `retention_status()`.

## 7. 화면 소스

`web/index.html`은 `#app` 하나와 `styles.css`, `app.js`만 로드한다. 쿼리 `?v=1.0.0.0-5`는 브라우저 캐시를 바꾸기 위한 값이다. 화면 파일을 고치면 이 값을 올린다.

`web/app.js`는 프레임워크 없이 DOM을 다시 그린다.

| 이름 | 역할 |
|---|---|
| `state` | 토큰, 선택 인스턴스, 현재 페이지, 필터. 토큰과 별칭은 `localStorage`의 `okedbmon_token`, `okedbmon_alias` |
| `MENUS`, `PAGE_META` | 상단 메뉴와 제목 |
| `api()` | `fetch`. 401이면 토큰을 지우고 로그인으로 돌아간다 |
| `boot()` | `/api/health`로 제품명을 읽고, 토큰이 있으면 대시보드로 들어간다 |
| `showPage()` | `pageOverview`, `pageCurrent`, `pageSession`, `pageSnapshot`, `pageLock`, `pageEvent`, `pageHistory`, `pageSql`, `pageTrend`, `pageReport`, `pageSettings`, `pageRetention` 중 하나를 호출 |
| `beginRender()`, `stillCurrent()` | 자동 갱신 중 늦게 도착한 이전 응답을 버린다 |
| `mount()`, `wire()` | 공통 헤더, 왼쪽 대상 목록, 메뉴를 붙이고 클릭을 연결 |
| `sessionBars()` | 시점별 Active Session. 막대 하나가 수집 1회. 선택하면 `state.sessionAt`으로 `/api/sessions/active`를 다시 부른다 |
| `sqlScatter()`, `sqlElapsedPoint()` | SQL 하나당 점 하나. 가로는 수행 횟수, 세로는 회당 수행시간(ms) |
| `openSqlDetail()`, `openSqlTrace()` | SQL 행에서 상세 창, 그 창에서 시점별 세션 샘플 |
| `donut()`, `spark()` | 첫 화면의 인스턴스 카드 |

`LIVE_PAGES`는 개요, Current, Active Session, Lock이다. 이 페이지는 주기적으로 `showPage()`를 다시 호출한다.

`web/styles.css` 상단 변수가 색이다. 헤더는 `#1b1b1b`, 강조는 `#e36b2c`다. 패널은 `.panel`, 표는 `.table-wrap`, 상세 창은 `.window-back` 안의 `.window`다.

## 8. 설정이 코드로 들어가는 위치

`config/default.properties`를 `load_properties()`가 읽어 `Store._seed()`에 넘긴다. 이후 화면과 보관 주기는 DB의 `env_setting`, `retention_policy`를 본다. 파일을 고쳐도 이미 저장된 키는 바뀌지 않는다. 화면의 Config와 보관 주기에서 바꾼다.

`config/agent.json`의 `password`는 에이전트만 읽는다. 수집서버 화면과 SQLite에는 다시 저장하지 않는다.

## 10. 고칠 때 같이 여는 파일

| 바꾸려는 것 | 먼저 여는 파일 |
|---|---|
| 수집 항목을 추가 | `agent/collectors.py`의 `envelope()`와 `collector/store.py`의 `ingest()`, 해당 테이블 |
| 조회 화면을 추가 | `web/app.js`의 `MENUS`와 `showPage()`, `collector/server.py`의 라우트 |
| 보관 종류를 추가 | `RETENTION_KINDS`와 화면 `pageRetention()` |
| 임계치를 추가 | `_raise_threshold_events()`와 `default.properties`의 `threshold.*` |
| 제품명이나 버전 | `collector/version.py`, `default.properties`의 `support.title`, `support.ver` |
| 화면 글자나 색만 | `web/app.js`, `web/styles.css`. 저장 후 `index.html`의 `?v=`를 올림 |
